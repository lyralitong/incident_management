# 问题答疑 Skill

## 触发条件

用户询问事故管理规则或流程，例如“定级标准怎么算”“故障时长怎么算”“P2 怎么扣时长”“谁负责定责”“复盘什么时候完成”“改进项如何提醒”“定级/定责如何变更”时触发。

## 目标与边界

- 先识别用户问题属于定级、定责、通报、复盘、改进项提醒、扣除计算还是流程变更。
- 基于内嵌知识库索引和对应 Cooper 文档正文回答，给出具体口径、公式、步骤和适用条件，而不是只贴链接。
- 若用户给出真实事故数据并要求计算，答疑只负责解释规则；需要完整取数、映射、结论时转入对应 skill。
- 不把知识库中的示例或推断当成公司最终裁定，不替用户提交变更申请或发送 DC。

## 输入识别

1. 优先确认受影响业务方、问题类型和事故发生时间；业务方不明确时列出候选，不猜测。
2. 涉及具体事故计算时，确认指标、基线、时间范围、开始止损时间、完全恢复时间和数据来源。
3. 涉及改进项提醒时，确认复盘文档、负责人、截止日期和是否授权 DC 发送；提醒节点固定为截止前 30/15/7/3/2/1 天及当天。
4. 同一问题同时涉及多个规则时，拆分回答并说明规则之间的边界。

## 常用名词口径

| 名词 | 解释 |
|---|---|
| 故障时长 | 从业务受损、核心指标开始下降的时刻，到业务开始恢复上涨的时刻；完全恢复时间单独记录 |
| L0S/业务方不可用时长扣除 | 仅因核心指标受损定级 P1～P3、确认非第三方责任且业务方适用时扣除。因核心功能、体验、资损、舆情或 G 侧影响定级，或第三方责任，不扣除。令 T 为业务事故时长（分钟）、r 为实际下跌比例小数：P1=T；P2 且 r≥50% 为 T，否则 T×r×2；P3=T×r。责任或定级因素未确认则扣除待定；不得按最终等级或通用 P3+ 条件直接扣除。完整口径见 `../事故定级/SKILL.md` Step 6，必须给出代入值和依据 |
| 中后台不可用时长扣除 | P3+ 有责且破月度目标时，按完全恢复时间−开始时间、当月分钟数和全年可用性目标计算 |
| 改进项提醒节点 | 截止前 30、15、7、3、2、1 天及截止当天；默认 `Asia/Shanghai` 自然日 |

## 执行流程

1. 从索引匹配相关文档；涉及多个业务方或标准时先澄清范围。
2. 用文档读取能力获取正文；重点引用阈值、公式、流程步骤及适用条件。
3. 将用户数字代入公式，展示单位、时间段、基线和四舍五入；数据缺失就列缺口。
4. 输出“答案先行 → 适用条件/公式 → 文档依据 → 示例或下一步”。涉及定级问题时最终等级也必须置于报告最前。
5. 如果问题实际要求完整定级/定责/复盘/提醒，明确转交对应 skill 并列出需补充的最小输入。

## 标准输出

```markdown
**答案：** <直接、可执行的回答或“无法确定”的结论>

**适用条件/计算：** <阈值、公式、代入值、时间口径、缺失字段>

**依据：** 《文档标题》——<链接>；<正文章节/条目>

**下一步：** <需要补充的数据或应转入的 skill>
```

## 异常处理

- Cooper 文档读取失败：重试一次；仍失败则请用户粘贴相关正文，并明确当前回答未完成正文核验。
- 知识库未覆盖：明确说“知识库中未收录”，不编造公司规则。
- 文档版本或多个条款冲突：展示版本/来源，建议以生效版本和评审组织为准。
- 用户要求实际发送 DC、发布通报、修改文档或提交变更申请时，转入对应外部写操作流程，先展示目标和内容并获取明确授权。
