# 故障数据源 Excel

定级完成时生成真实 `.xlsx`，并在报告“故障数据源”字段中提供可点击文件链接。此文件是监控自动取数的证据交付，不要求用户提供 Excel。

## 数据范围和对齐

- 对每个指标，取最终确认的开始下跌分钟前 10 分钟至开始恢复分钟后 10 分钟，含首尾分钟。终点是开始止损，不是完全恢复。开始恢复时间取谷底之后首个高于谷底值的分钟桶；其后至少 2 个分钟桶只用于确认候选未被新低/重新探底推翻，不得把开始恢复时间顺延到确认分钟。例：14:48=9,590 为最低点，14:49=9,675 首次回升，14:50=10,041、14:51=10,844 确认持续上升，则 Excel 窗口终点以 14:49 为开始恢复，再向后取 10 分钟；谷底 14:48 与确认值应在计算依据中留痕。
- 时间统一转换为 Asia/Shanghai。输入故障端点若有秒，取其所在分钟作为对应分钟桶；端点的原始精度保存在“计算依据”。监控记录的 `__time` 必须在整分钟；不能靠改写时间戳把非分钟数据伪装成分钟数据。
- 同比日期表示故障开始日期的历史对应日期。同比窗口通过整体平移日期获得，时分及跨午夜的相对天数保持不变，不能把跨日记录强塞回同一天。
- 两端都包含，每行一分钟。监控接口若用左闭右开窗口，请求终点在所需最后一分钟之后再加 1 分钟，导出时裁剪。
- 前后 10 分钟只取证；故障计算使用故障分钟范围。脚本的 `fault_minute_points` 是包含两端的分钟点数，对应现有 Skill 的统计口径，不能将其静默改成端点相减的分钟数。

## 布局（按用户截图）

| 单元格/区域 | 内容 |
|---|---|
| A1 | 空白 |
| B1 | 最终同比日期，Excel 日期格式 `yyyy/m/d` |
| C1 | 故障开始日期，Excel 日期格式 `yyyy/m/d` |
| A2 | 时间 |
| B2、C2 | 实际业务指标名称，如“发单数”或“完单量” |
| A3 起 | 每分钟时间，显示 `hh:mm`；跨午夜时显示完整日期和时分 |
| B3 起 | 同比日期该分钟的原始指标值 |
| C3 起 | 故障当天该分钟的原始指标值 |

每个指标单独一个对比 sheet；多指标可放在同一工作簿。脚本另生成“完整时间明细”sheet，保存故障日期、同比日期各自完整时间和值；“计算依据”sheet 保存 A、B、I、C、比例、原始字段、指标 ID、维度、时区和数据源。

真实零保留数值 `0`；缺失显示“缺失”，不能插值或补零。故障窗口中任一侧有缺失，则 A、B、I 和比例均不计算；只在缓冲区缺失时，保留计算结果并披露缺口。重复分钟、非数字、负值、无穷值或多维度未拆分的数据会报错，应先核对监控请求，不应伪造修复。

## 脚本输入与调用

依赖 Python 3.9+、`openpyxl`。先检查运行环境；可用时复用工作区提供的 Python 和库。脚本只读取已取数的 JSON，不请求监控、不定级、不执行发送。

每个输入 JSON 对应一个业务指标和一个最终同比日期。示例中的记录数组必须替换为真实监控返回的完整窗口，不能作为真实事故数据使用：

```json
{
  "business": "货运",
  "metric_name": "发单数",
  "metric_id": "freight_order_create_and_dispatch_cnt",
  "unit": "单",
  "incident_start": "2026-10-12T14:41:00+08:00",
  "recovery_start": "2026-10-12T14:51:00+08:00",
  "baseline_date": "2026-09-21",
  "baseline_day_total": 800000,
  "source": "observe-cn.woater_query_metric_timeseries",
  "standard_url": "https://cooper.didichuxing.com/knowledge/2204014852542/2205506034112",
  "filters": {"说明": "这里记录本次实际使用的维度过滤"},
  "incident_records": [
    {"__time": "2026-10-12T14:31:00+08:00", "num": 12286}
  ],
  "baseline_records": [
    {"__time": "2026-09-21T14:31:00+08:00", "num": 12792}
  ]
}
```

`baseline_day_total` 必须是已取到的同指标同比日全天总量，不能用导出窗口总量推算。字段缺失/为零时，累计比例将显示无法计算。脚本分别按 `order_cnt → num → y` 选择两侧实际字段，记录选择结果；不要预先把零值过滤掉。

默认 I = max(B−A, 0)。若标准要求其他受影响总量公式，Agent 必须从真实数据算出 I 后增加 `impact_amount`（数字）和 `impact_formula`（完整公式及代入值）；脚本记录来源而不自行猜测公式。无论是否自定义影响量，故障窗口缺失时仍不输出确定结果。

在 Skill 目录下执行（路径由 Agent 按实际文件填写）：

```bash
python3 harness/scripts/export_incident_evidence.py \
  --input /absolute/path/发单数证据.json /absolute/path/完单量证据.json \
  --output /absolute/path/故障数据_货运_20261012_144100.xlsx
```

输入文件由 Agent 从已有监控结果整理，用户无需补数。输出文件名包含业务方和故障开始日期时间；若已存在则换一个带版本后缀的名字，脚本不会覆盖原文件。报告中链接到实际生成文件的绝对路径，路径含空格时使用尖括号包裹 Markdown 链接目标。

## 交付校验

1. 回读生成文件，核对两行表头、首末分钟、每分钟连续性及双方日期；不得只凭脚本退出码声称内容正确。
2. 在故障窗口内分别求和并核对 A、B、I、下跌比例以及 I/C，确保缓冲区数据没有参与计算。
3. 检查终点分钟是否包含、缺失是否已披露、真实零是否保留、字段及过滤维度是否和报告一致。
4. Excel 生成失败应返回错误并标明交付未完成；只有已有文件可作为“故障数据源”链接。未确认同比日/起止时间时不编造 Excel，用报告说明未生成原因。
